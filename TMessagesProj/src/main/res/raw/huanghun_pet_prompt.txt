====================黄昏客户端桌宠动态角色制作完整文档====================
适用：移动端黄昏客户端
核心要求：不是把原图简单切帧，而是把角色做成真正会动的桌宠。

重要前置说明：
仅输出 黄昏桌面宠物.zip 资源压缩包。
禁止生成 EXE、APK、DLL、JS、Python、Shell 脚本等任何可执行程序。
全部运行逻辑、触摸交互、时间读取、天气读取、随机调度、边界判定由移动端黄昏客户端完成。
本次只产出：透明 PNG 角色素材、动画帧、JSON 配置、对白文本、说明文档。

一、角色制作原则：必须动态重构，不做原图静态复制
1. 使用用户上传的人物图片作为角色外观基准。
2. 保留角色的发型、脸型、服装、身材比例、整体气质和照片辨识度。
3. 但不要被原图姿势锁死。必须根据动画类型重新设计动作。
4. 用户上传的只是“角色长什么样”，不是“每一帧都必须长这样”。
5. 所有动作都要符合人体结构和重心逻辑，禁止出现肢体错位、手指畸形、双腿融合、身体悬浮等错误。

二、动作重构规则
根据不同动画，角色姿势必须主动变化：

1.待机呼吸
角色保持自然站姿，身体有轻微呼吸起伏，头发和衣摆有轻微晃动。
可以眨眼、轻微偏头，但不要长时间保持原图完全静止姿势。

2.自主行走
角色必须从一个位置移动到另一个位置。
动作要求：
- 双腿交替迈步
- 身体重心左右转移
- 手臂自然摆动
- 头发和衣摆随步伐轻晃
- 不能只是原地左右摇晃冒充行走

3.自主小跳
角色从地面起跳，双脚同时离地，落地后恢复站姿。
动作要求：
- 起跳前微微下蹲蓄力
- 起跳时身体向上
- 落地时有轻微缓冲
- 双臂可以自然抬起保持平衡
- 不能双脚贴地假装跳跃

4.左右摇晃
角色站立重心稳定，身体左右轻晃。
可以一只手抬起挥动，也可以双手自然摆动。
不要保持原图僵硬姿势。

5.原地转圈
角色原地旋转一圈或半圈。
动作要求：
- 身体有明显旋转方向
- 头发、衣摆产生旋转惯性
- 手臂自然展开或轻抬
- 转完后回到正面站姿
- 不能只改变背景或镜头，人物必须真的在转

6.蹲下休息
角色从站立变为蹲下休息。
动作要求：
- 膝盖弯曲
- 身体重心下沉
- 手臂可以搭在膝盖附近
- 头部可以轻微低垂
- 不能只压扁身体模拟蹲下

7.探头张望
角色走到屏幕边缘，身体前倾探头向外看。
动作要求：
- 上身前倾
- 一只手或双手扶在身体侧边
- 头部有观察方向
- 脚下保持稳定支撑
- 不能像纸片一样平移

8.开心欢呼
角色表现出明显开心。
动作要求：
- 可以双手举起
- 可以挥手
- 可以轻微蹦跳
- 表情更明亮
- 不要只是轻微晃动

9.委屈emo
角色表现低落。
动作要求：
- 身体微微佝偻
- 头部低垂
- 肩膀下沉
- 手臂自然下垂或贴近身体
- 情绪要明显，不能只是换一句台词

10.打哈欠
角色困了，张嘴打哈欠。
动作要求：
- 嘴巴张开
- 眼睛半闭或闭上
- 一只手可能抬起捂嘴
- 身体有轻微困倦下沉
- 不要保持原图清醒姿势

11.偷吃零食
角色停下吃东西。
动作要求：
- 一只手拿零食
- 另一只手自然辅助
- 嘴巴有咀嚼动作
- 身体微微前倾
- 表情放松有趣

12.惊吓一抖
角色突然被吓到。
动作要求：
- 身体猛地一颤
- 肩膀抬起
- 头部稍微后仰
- 双手可能靠近胸前
- 表情惊讶
- 不能只是轻微闪烁

13.挥手告别
角色挥手说再见。
动作要求：
- 一只手明显挥动
- 手臂从肩部到手掌结构完整
- 身体轻微侧转
- 表情友好
- 不能只做小动作敷衍

14.淋雨发抖
角色在雨中发抖。
动作要求：
- 身体轻微缩起
- 肩膀颤抖
- 双手靠近身体取暖
- 头发和衣服略湿
- 表情委屈或冷

15.晒太阳伸懒腰
角色晒太阳，舒展身体。
动作要求：
- 双臂向上伸展
- 身体拉长
- 头部后仰或侧仰
- 表情舒服放松
- 不能保持原图缩着的姿势

16.害羞躲闪
角色害羞，扭过脸回避。
动作要求：
- 头部转向一侧
- 肩膀微缩
- 一只手靠近脸边或胸前
- 表情害羞
- 身体要有回避动作

17.跺脚生气
角色生气跺脚。
动作要求：
- 一只脚抬起再落下
- 身体重心变化
- 双手叉腰或摆动
- 表情不满
- 不能只做轻微抖动

18.发呆放空
角色停下来发呆。
动作要求：
- 眼神失焦
- 身体静止但有轻微呼吸
- 头部微微歪斜
- 手臂自然下垂
- 比待机要更空、更慢

19.挠头疑惑
角色疑惑挠头。
动作要求：
- 一只手挠头
- 另一只手自然下垂
- 头部微偏
- 表情疑惑
- 手掌和头发接触要自然

20.捂嘴偷笑
角色偷偷笑。
动作要求：
- 一只手捂嘴
- 肩膀轻抖
- 身体微微前倾
- 表情想笑又忍住
- 不能只改变脸部细节

21.犯困点头
角色困得一点一点。
动作要求：
- 脑袋缓慢下垂
- 身体有困乏感
- 眼睛半闭
- 肩膀下沉
- 节奏要明显

22.拍手鼓掌
角色开心鼓掌。
动作要求：
- 双手在胸前拍动
- 手臂结构完整
- 身体随节奏轻晃
- 表情开心
- 不能只做很小动作

23.失落垂头
角色长时间没人理，变得失落。
动作要求：
- 头部明显低下
- 肩膀下沉
- 身体失去精神
- 手臂无力下垂
- 比委屈更安静、更低落

24.被点击
用户点击后角色要有明显反馈。
动作要求：
- 身体轻颤
- 头部转向点击方向
- 表情惊讶或害羞
- 不能没有动作变化

25.被拖动
角色被拖动时身体倾斜。
动作要求：
- 身体随拖拽方向倾斜
- 头部有惯性
- 衣摆和头发有延迟跟随
- 不能像原图一样硬邦邦移动

26.压扁后弹回
角色被压扁后弹回。
动作要求：
- 身体先纵向压扁
- 然后快速回弹
- 回弹时有轻微夸张动作
- 最后恢复正常比例
- 不能只做透明度变化

27.睡觉休眠
角色进入睡眠状态。
动作要求：
- 闭眼
- 身体放松
- 可能轻微侧躺或坐着睡
- 头顶有 Zzz 符号
- 呼吸很慢

28.午夜彩蛋
凌晨零点触发特殊动作。
动作要求：
- 可以仰望月亮或星星
- 可以神秘挥手
- 可以安静微笑
- 可以做一个午夜专属小姿势
- 氛围要和白天不同

三、重点动作修复要求
1.如果原图只有一只手抬起，制作跳跃动画时，角色双手可以一起抬起。
2.如果原图是静态站立，制作行走动画时，必须让双腿交替迈步。
3.如果原图没有表情，制作情绪动画时，必须通过头部、肩膀、手臂和身体姿态表达情绪。
4.所有动作都要有起势、过程、恢复三个阶段。
5.每一帧都要保持同一个角色，不能换脸、换发型、换服装。
6.动作幅度可以夸张，但人体结构必须自然。

四、图片完整性判断
1.完整全身角色：
启用全部 28 套动画。
manifest.json 设置 "partial_body": false。

2.半身/头像/裁切角色：
禁用行走、跳跃、转圈、蹲下、跺脚等依赖完整身体的动作。
manifest.json 设置 "partial_body": true。
但保留上半身动态能力，仍然制作待机、被点击、被拖动、睡觉、害羞、委屈、开心、偷笑、疑惑、打哈欠等动作。

五、输出要求
1.全部图片去除背景，透明 PNG。
2.所有帧尺寸统一。
3.角色脚底锚点对齐。
4.角色比例不变。
5.动作连续自然。
6.输出 pet_pack.zip。
7.包内只允许图片、JSON、对白、说明文档。
8.不生成任何程序代码。

六、最终原则
用户上传的是角色外观，不是最终动作模板。
只要保留角色外观、服装和辨识度，就可以根据动画类型重新摆姿势。
真正有趣的桌宠，不是“原图会晃一下”，而是“这个角色真的会做不同的事”。
七、黄昏客户端强制兼容格式（必须严格遵守）

1. 压缩包根目录必须直接包含 manifest.json，不要再套多层目录。若必须使用外层目录，只允许最外层只有一个目录，manifest.json 位于该目录根部。

2. manifest.json 必须是 UTF-8 JSON 对象，至少包含以下字段：
{
  "pack_version": "1.0.0",
  "pack_name": "桌宠名称",
  "character_name": "角色名称",
  "partial_body": false,
  "default_animation": "idle",
  "animations": { ... }
}

3. 全身角色将 partial_body 设置为 false；半身、头像或缺少完整腿部的角色必须设置为 true。不要因为缺少全身动作而伪造全身帧。

4. 动画文件必须使用以下固定目录和命名：
animations/动作英文名/frame_01.png
animations/动作英文名/frame_02.png
animations/动作英文名/frame_03.png

所有帧必须是透明 PNG，编号从 frame_01.png 开始连续递增，不能使用 frame1.png、中文文件名或混用 jpg/webp。每套动画的 manifest 配置必须使用整数 frames，例如：
"idle": {"frames": 4, "fps": 4, "loop": true, "frame_prefix": "frame_"}

5. 动画英文名只能从以下列表中选择，不得自行改名：
idle、walk、jump、sway、spin、squat、peek、happy、sad、yawn、eat、scared、bye、rain、stretch、shy、angry、blank、confused、giggle、sleepy、clap、disappointed、touched、dragged、squash、sleep、midnight。

6. idle 是唯一必须提供的动画。其他动画可以因人物不适合而省略，但 manifest 中不得声明不存在的动画帧。partial_body 为 true 时，优先提供 idle、touched、dragged、happy、sad、shy、giggle、yawn、sleep 等上半身动作。

7. 对白文件必须放在：
dialogue/dialogues.json

对白文件必须使用以下结构，dialogue_pools 中的键必须使用上面规定的动画英文名：
{
  "character_name": "角色名称",
  "dialogue_pools": {
    "idle": {"lines": ["对白1", "对白2"]},
    "walk": {"lines": ["对白1", "对白2"]},
    "touched": {"lines": ["对白1", "对白2"]},
    "squash": {"lines": ["对白1", "对白2"]}
  }
}

每个 lines 必须是字符串数组，每组至少提供 3 条中文对白。不要把对白写在 manifest 中，不要使用 dialogue_pools 以外的顶层结构替代它。可以额外提供 weather_dialogue 和 time_greetings，但不能替代 dialogue_pools。

8. manifest 中不要写 supports_dialog: false；只要提供 dialogue/dialogues.json，就应当生成对白。对白必须使用 UTF-8 编码，文件大小不超过 1 MB。

9. 预览图优先放在根目录 preview.png；如果不提供 preview.png，必须保证 animations/idle/frame_01.png 存在，客户端会自动生成预览图。

10. 输出前必须执行自检：确认 manifest.json 能被标准 JSON 解析；确认 animations/idle/frame_01.png 存在；确认所有 manifest 中声明的动作目录和帧数量真实存在；确认 dialogue/dialogues.json 能被解析且至少有 idle、touched 两组对白；确认 ZIP 内没有 exe、apk、dll、jar、so、bat、cmd、sh、ps1、js、lua、py、class 等可执行或脚本文件。
