## 1. 聊天搜索

在“聊天”搜索页的搜索栏／分类标签下、最近访问和结果上方加入透明的双开关行，沿用客户端主题与壁纸背景。无消息搜索的选择模式不显示此行。

| 功能 | 默认状态 | 规则 |
| --- | --- | --- |
| 去重搜索 | 开启 | 同一群或频道中，同一实际发送者只显示第一条符合条件的消息。同一发送者在不同群／频道仍分别显示；私聊不做发送者去重。 |
| 精确搜索 | 关闭 | 开启时，消息原文或媒体说明文字必须与输入词完全相同。例如“你好”不会匹配“你好啊”“啊你好”“你好 ”或“你好\n”。不做大小写、空白或标点归一化。 |

两个开关可同时使用：先进行精确匹配，再去重，避免不精确的结果占用发送者名额。开关状态在当前搜索页面实例中保留，不写入永久设置。

全局消息搜索、论坛搜索以及按聊天／日期筛选的纯消息搜索都接入过滤。媒体、链接等独立分类的原有搜索逻辑不应用此过滤；联系人和聊天名称的搜索规则也不改变。

保留已加载的原始消息，切换开关时即时重建结果，关闭后可恢复之前隐藏的内容。分页使用服务器原始游标，而非过滤后最后一条消息；整页被隐藏时继续补页，并加入在途请求、旧响应、重复游标、错误响应与删除补位保护。

频道或匿名发言没有公开真实用户身份时，以 Telegram 提供的可见发送者／频道身份去重，不推断隐藏身份。

## 2. 所有协议制作结果的分享

本机账号提取、Session／JSON／tdata 转换、外部账号提取与 Passkey 制作共用完成结果页。嵌入式完成页和原生回退弹窗都增加“分享”按钮。

分享流程：

1. 点击完成页“分享”。
2. 打开客户端内置的多选收件人界面，可选择用户、可发送的群或频道，并使用客户端原有账号切换入口。
3. 选择接收方后，显示文件名、接收方与登录凭据风险确认。
4. 用户明确确认后，生成的 ZIP 压缩包才进入客户端正常文档发送队列，发送至所选接收方；如需 Stars 费用，沿用原生费用确认。

不调用 Android 系统分享面板，不自动上传，不自动选择接收方。保留分享备注、通知选项、定时／重复参数与有效论坛话题。没有已登录账号时提示先登录。

原生端仅接受制作结果文件快照，JavaScript 分享桥不接收文件路径或接收方参数。分享前与发送前校验文件、账号及话题，防止文件丢失、变化、重复点击或旧回调导致错误发送。取消风险确认不会发送，收件人选择器可继续使用。

协议和 Passkey 压缩包包含可登录账号的授权信息或私钥；接收方可能使用它控制账号。请仅分享本人有权处理的凭据，并认真确认可信接收方。

## 3. 外部应用分享文件的稳定性加固

Android `ACTION_SEND_MULTIPLE` 入口现在由 `SharedFileUriHelper` 统一收集 `EXTRA_STREAM`、`ClipData` 与数据 URI，忽略空值／不支持的 URI scheme，并去重。多文件按每个 URI 的 MIME 类型分别判断图片／视频或文档，不再仅凭发送方给出的总 MIME 类型把整批附件当作同一媒体类型。单个 ClipData 项、类型查询、路径查询、缓存复制或权限异常会在单附件范围内记录并跳过，避免中断其余附件；ZIP、APK、PDF 和未知 MIME 保留走文档发送路径。无可用附件时提示无法读取内容。

当前没有用户提供的崩溃堆栈、设备型号／Android 版本或可复现步骤，因此不能断言已确认真实设备崩溃根因。已有实现的 Intent 处理外层也包含运行时异常兜底；本次修改是针对可从源码确认的多 URI 批次隔离与混合 MIME 风险进行加固。新增 JVM 测试使用 Android API 桩验证 URI 解析契约，无法替代真实内容提供者权限、系统收件人选择器或发送队列的真机测试。
